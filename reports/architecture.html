01Delivered system

A containerized CDA validation API, local browser workspace, Node/TypeScript client and command-line interface. Existing in-process JavaScript APIs remain available independently of the service. Submitted XML is not persisted or sent to an external validator.

This report describes the 2.0.0 implementation. This is engineering evidence, not clinical certification or a claim to be the fastest validator.

Patched Java 25 LTS hosts the HTTP adapter and engine. Saxon-HE 12.9 executes stylesheets compiled with SchXslt 1.10.1. The JDK XSD validator checks the pinned CDA schema; Gson serializes reports. No database, message broker, Node process or application framework is required inside the runtime container.

Startup verifies the extracted asset inventory, compiles schemas and profile executables once, and loads immutable operator terminology indexes. Every document owns its parser, schema validator, transformer, line lookup and bounded finding collector. There is no patient-document or result cache.

The releases use XPath 1.0 coercions. Compilation retains backwards-compatible semantics, makes severity explicit and assigns stable IDs to unnamed assertions. Vocabulary comparisons use complete tokens rather than substring membership. List-valued name attributes are checked token by token. Predicate-scoped vocabulary variables retain their own context.

Python tools prepare sources, import authorized data, verify runtime versions, check upstream releases, exercise memory pressure and generate this report. The browser is ordinary HTML/CSS/JavaScript with no external scripts, fonts, trackers or analytics.

04What validation completion means

The stated scope is pinned CDA XSD and C-CDA Schematron with reviewed local supplements. This is not a general FHIR StructureDefinition validator and does not certify clinical accuracy.

FieldMeaning
executionCompleteConfigured engine stages finished without failure.
validationCompleteExecution finished, supported document-level template matched, findings were not truncated, generator replacements were reviewed, and every applicable check was determinate.
validComplete within the stated scope and no errors.
invalidErrors found; completeness still needs inspection.
incompleteNo errors found, but execution or applicable coverage is incomplete. This is not a pass.

A completed invalid report is expected when checks finish and find errors. Missing datasets generate coverage findings at applicable locations, even when advisory warnings are hidden. An absent optional binding that a document does not use does not make every document incomplete. Dataset readiness remains separately visible.

Six restored invariants cover person names, procedure membership, procedure timestamps and a three-set location union. All omitted binding locations receive checks or explicit unknown coverage. Three CarePlanAct unions allow base CDA Act/Observation children without invented template IDs; 103 scoped assertions restore root cardinalities, fixed values, required bindings and II constraints alongside XSD and narrower profile rules.

Indeterminate cases include unsupported SNOMED expressions, standalone CPT/HCPCS modifiers, mismatched declared terminology editions, ambiguous scalar vocabulary values, insufficient timestamp precision, excessive grammar complexity and unvalidated BCP 47 extension semantics. Private-use language tags remain supported. Nested templates firing cannot replace a supported root document template.

05Operator terminology and licensing

The verified local pack contains 29 snapshots / 1,013,055 membership entries, with 28 active indexes and two grammars. It enables six supplemental invariants and 54 catalog binding checks. Public images and npm packages omit this operator data.

UMLS 2026AB plus LOINC Complete 2.83 supplies reviewed US Core condition (262,583 pairs) and procedure (274,743 pairs) sets. SNOMED descendants use source-asserted AUI hierarchy paths and source concept IDs, not shared UMLS CUIs. The 62,110-pair Procedure hierarchy exactly matches an independent VSAC snapshot. Archive hashes, source row counts, recipe counts and source editions are recorded.

Source editions include SNOMED US September 2026, CPT 2026, CDT 2025, HCPCS 2026, ICD-10-CM/PCS 2027, ICD-9-CM 2014 and LOINC 2.83. These are the reviewed archive's editions; older data is never relabeled as a new edition. Explicit document version mismatches are incomplete rather than silently evaluated against another version.

LOINC document types are cross-checked against primary SCALE part links. UCUM uses its pinned essence grammar. BCP 47 uses the November 18, 2026 IANA registry and extension singleton registry; extension key/type semantics are not claimed.

Remaining dataset: NUBC discharge status. An operator must supply an authorized complete expansion to check that binding. No NUBC source was present in UMLS and no scraped substitute is bundled. Applicable checks remain incomplete until installed.

Application code is MIT licensed; terminology has separate terms. A free application, UMLS access or a notice does not automatically establish redistribution or product rights. The software does not accept licenses or collect credentials. CPT/ADA and other applicable permissions remain the operator's responsibility. See the AMA guidance and LOINC license.

06Patched Java and security boundaries

Build and runtime use Temurin 25.0.5.1+2 LTS on AMD64 and ARM64. This contains the November fix for CVE-2026-114938. Java 27 is the newer feature line; its official image still had mixed architecture patch levels when reviewed. This choice uses the latest patched LTS available for both supported targets.

Images are digest-pinned. CI verifies the actual JVM version/vendor in the built image, and the weekly upstream watch flags a newer selected LTS release. The API exposes the actual runtime. Older published previews do not receive this patch until rebuilt and released.

DTD declarations and entities are forbidden, including UTF-16 import declarations. Runtime resource resolution denies the network and paths outside trusted assets. Public routes accept XML and installed profile IDs, never arbitrary server files, URLs or executable Schematron. Input bodies, filenames, findings and parser diagnostics are not logged.

The container runs as non-root UID/GID 10001, with a read-only root filesystem, bounded temporary storage, dropped capabilities and no-new-privileges. Shared deployments need an authenticated HTTPS gateway and deliberate logging/retention controls. Findings can contain submitted values; callers must handle them appropriately.

07API, UI and interoperability

RoutePurpose
POST /v1/validateJSON containing XML text, profile and warning settings; structured findings.
GET /v1/profilesProvenance, effective/historical coverage, data readiness and active limits.
GET /v1/versionApplication, engine and actual Java runtime/vendor.
GET /health/live and /health/readyHealth probes independent of validation queue contention.
GET /openapi.jsonOpenAPI 3.1 contract.

Findings include severity, stage, source message, rule ID, XPath, assertion test, pattern/context and available line/column. HTTP 200 means a report was produced, not a validation pass. Operational errors use distinct HTTP statuses.

The UI accepts an XML file, drag-and-drop or pasted text. It shows installed profiles, data/coverage limits, stage status, findings, filters, line navigation and a downloadable JSON report. Input revisions guard delayed file/example loads and stale validation responses. User-provided content is inserted as text. The blue/slate palette is independent of workplace branding, with red errors and amber coverage notices.

Language-neutral HTTP/JSON lets other technologies use the container. The npm package retains validate, validateAsync, both batch APIs, parseSchematron and cache APIs; their synchronous/Promise contracts remain. The legacy interpreter is partial Schematron and does not add XSD validation. The additive createClient() and CLI use the modern service. Node 22.12+ is required.

08Bounded capacity and memory

Default XML limit is 20 MiB decoded UTF-8, configurable with MAX_XML_MIB. Worst-case JSON escaping is allowed separately: six times the XML limit plus 64 KiB. Streaming decode avoids keeping the entire serialized body in memory.

Six requests may be admitted across upload, queue and validation; two workers execute validation. Uploads share a quarter-heap budget with conservative reservations and a fair queue. An admitted request waits on its original connection, up to 30 seconds, without requiring a retry. A full overall queue returns 429; an expired upload wait returns 503. Health checks remain available.

Increase both Java heap and container memory to allow more concurrent large uploads. More heap does not by itself guarantee faster XPath execution. Full terminology indexes are checked against estimated heap capacity before loading. The tested full-pack configuration uses a 1 GiB heap and 1.5 GiB container limit.

VALIDATOR_MEMORY_LIMIT=3g VALIDATOR_JAVA_OPTIONS=-Xmx2g docker compose up -d

Other limits: 128 levels, 100,000 elements, 256 attributes per element, 2,000 findings, bounded 4,000-character messages, a 65-second HTTP read window and a separate 30-second validation deadline. Cancellation is cooperative; guaranteed termination of arbitrary XPath operations would require process-isolated workers.

11Deployment, updates and ownership

docker compose up --build -d
# Open http://localhost:17643
# Select a different host port if necessary:
CDA_VALIDATOR_PORT=17644 docker compose up -d

The service binds locally by default. Compose mounts operator terminology read-only. The multi-stage build separates verified asset preparation, Java compilation/tests and the minimal runtime. The release workflow publishes versioned AMD64/ARM64 images with SBOM/provenance; merging alone does not publish. npm client and container are separate artifacts.

Weekly checks compare official HL7 releases and the selected Java LTS against their locks. Updates require source, coverage, test and memory review; no silent runtime rule updates occur.

Changes use descriptive work branches and owner-authorized PRs. No development-tool names are allowed in branch names. No direct merges/pushes to main are allowed. The owner can merge their own PR after checks. Public issues remain enabled. GitHub cannot prevent outside PR creation on a public repository while independently retaining public issues; merge policy is enforced instead.

Merges and releases require the owner's authorization. This report records implementation verification; current artifact availability is recorded on the GitHub release page. Publication does not turn the product into full clinical certification.
