OPERATOR GUIDE

Your terminology. Your local validator.

Install authorized, versioned terminology in a read-only data volume. The application does not accept a license on your behalf, include CPT data, or send clinical documents to terminology services.

1. Download the data you are authorized to use

A UMLS account or a free download does not establish redistribution rights for every included source. Check the terms for your deployment. The software license does not license CPT or other terminology data.

SourceWhat to obtain
VSACComplete SVS XML or FHIR expansions for the exact value-set canonicals listed in /v1/profiles. Review counts, editions and retired status.
LOINCThe authorized LOINC release and any required accessory tables. LOINC permits redistribution subject to its license; user-supplied data is supported here. A UMLS edition can also contain LOINC.
CPTAn authorized electronic dataset under a license covering your intended use. A notice or a codebook purchase does not itself authorize distribution. This application does not bundle CPT. Operator-supplied data does not automatically exempt a CPT-dependent product from AMA product licensing.
HL7 / CDC / CMS / source systemsComplete, versioned expansions of the remaining named value sets. Similar OIDs from different publishers are not interchangeable.
UCUM and IANAUCUM essence definitions; the language-subtag registry and language extension registry. These grammar-based sets cannot be replaced by a finite list of sample codes.

2. Prepare a local data folder

Use the repository’s scripts/import-svs.py for reviewed SVS exports, then scripts/import-fhir-terminology.py for complete FHIR ValueSet expansions. Use scripts/import-loinc.py with your locally downloaded LOINC Complete 2.83 archive for US Core document types; it verifies the pinned archive and cross-checks the Doc scale against primary part links. Each importer records counts, versions, source hashes and content hashes. FHIR imports require an explicit URI-to-CDA-OID mapping and reject partial expansions. Review the source edition; more recent data is not automatically equivalent to the implementation guide’s intended edition.

See the detailed setup commands and manifest format. Keep raw exports and normalized indexes out of Git, npm packages and public images.

3. Install the C-CDA 2.1 vocabulary locally

The upstream mixed-license voc.xml contains CPT entries and is omitted from new public images. Obtain an authorized copy matching the pinned upstream release, then install it into the terminology folder. The tool verifies the expected SHA-256 before installation.

docker run --rm --entrypoint java \
  --user "$(id -u):$(id -g)" \
  -v "$PWD/terminology:/app/terminology" \
  -v "/path/to/authorized/voc.xml:/input/voc.xml:ro" \
  IMAGE -cp /app/app.jar org.cdavalidator.TerminologyTool \
  install-legacy /input/voc.xml

Replace IMAGE with the image version you use. Until this vocabulary is installed, C-CDA 2.1 schema validation runs and its Schematron stage reports that terminology setup is required. The legacy npm API still accepts caller-supplied schemas and vocabulary.

4. Mount, check and restart

docker run --rm --entrypoint java \
  -v "$PWD/terminology:/app/terminology:ro" \
  IMAGE -cp /app/app.jar org.cdavalidator.TerminologyTool doctor

The doctor command exits with code 2 while datasets are missing. Mount the folder at /app/terminology when starting the service, or set TERMINOLOGY_DIR to a read-only local directory. Compose uses CDA_TERMINOLOGY_DIR for the host folder. Restart after changing installed data; the running engine uses an immutable verified snapshot.

Dataset readiness and validation coverage are separate. Installing all datasets does not certify complete C-CDA 5.0 conformance. Read the profile’s remaining coverage limitations before relying on a result.
